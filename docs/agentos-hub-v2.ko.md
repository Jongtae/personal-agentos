# AgentOS Hub v2 제품 기준

## 한 문장

**AgentOS는 사용자의 Mac에서 지속적으로 실행되며 개인 기억·맥락·도구·권한·비서·작업 기록을 관리하고, 개인 Telegram 봇을 통해 Codex·Claude Code 같은 AI 실행 엔진으로 실제 일을 처리하는 개인 에이전트 런타임이다.**

## Mac, AgentOS, AI 실행 엔진의 구분

| 층 | 책임 | 저장하는 것 |
| --- | --- | --- |
| Mac | 하드웨어, 운영체제, 사용자의 로그인 환경, 로컬 파일 | 운영체제와 사용자가 소유한 원본 파일 |
| AgentOS | 개인 상태·작업 큐·비서·도구·승인·근거·복구를 관리하는 항상 실행되는 런타임 | 대화, 메모, 컨텍스트, 연결 범위, 작업·도구 기록, 승인 상태 |
| Codex / Claude Code | AgentOS가 특정 작업에 호출하는 추론·실행 엔진 | 각 제품의 자체 세션. AgentOS 상태의 원본이 아님 |
| AgentOS control plane | 개인 봇 생성, 순간 중계, 체험 권한, 업데이트 | 최소 계정·페어링·운영 메타데이터. 메시지·문서·기억 원문은 저장하지 않음 |

AgentOS는 단순 중계기가 아니다. 요청을 어느 비서에 배정할지 판단하고, 허용된 컨텍스트만 제공하며, MCP 도구 실행과 승인·취소·재시도·증거 기록을 소유한다. Codex나 Claude Code를 교체해도 AgentOS의 개인 상태와 권한 계약은 유지된다.

AgentOS 런타임은 Mac의 일반 홈 디렉터리와 분리된 사용자별 OCI 컨테이너 또는 관리형 경량 VM에서 동작한다. Mac 동반 앱은 최소 조정자이며, 승인한 읽기 전용 문서만 중재 경계로 런타임에 전달한다. 각 AI 작업은 그 안에서도 임시 격리 공간을 사용한다.

## 사용자 경험

1. 사용자는 소비자용 Mac 설치 프로그램으로 AgentOS를 설치한다. Homebrew는 개발자와 셀프호스터 경로다.
2. AgentOS가 Codex·Claude Code 상태를 확인하고 공식 로그인만 안내한다. API 키 입력은 기본 경로가 아니다.
3. 사용자는 AgentOS 관리 봇을 통해 자신의 Telegram 개인 봇을 만들고 Mac 런타임과 페어링한다.
4. 이후 Telegram에서 자연어로 조사·문서·기록 업무를 요청한다.
5. AgentOS는 적합한 비서를 선택하고, 엔진에게 AgentOS MCP 도구만 제공해 일을 수행한 뒤 출처·상태·결과를 Telegram으로 돌려준다.
6. 사용자가 켠 경우에만 클립보드 텍스트·공개 URL이 로컬 컨텍스트 인박스에 축적된다.

Mac이 꺼져 있으면 AgentOS는 일을 실행하지 않는다. 개인 봇은 오프라인 상태를 명확히 알리고 Telegram에 남아 있는 업데이트를 Mac이 돌아온 뒤 처리한다.

## 권한과 데이터 경계

- 읽기·조사·정리·메모는 비서 정책 안에서 자동 실행할 수 있다.
- 외부 전송, 파일 수정, 계정 변경, 결제는 별도 승인을 요구한다.
- 실행 엔진은 사용자별 AgentOS 런타임 안의 빈 임시 작업공간에서 시작하며 임의 셸, 로컬 파일, 직접 네트워크 권한을 기본으로 받지 않는다. AgentOS 런타임은 홈 디렉터리 전체나 Docker 소켓을 마운트하지 않는다.
- 검색·연결 문서·메모·검토 역할은 AgentOS MCP 도구를 통해서만 접근한다.
- 외부 엔진에는 비서별로 사용자가 미리 허용한 컨텍스트만 전달한다.
- 민감한 클립보드 값은 저장·전달 전에 폐기한다.

## 공식 기본 비서

- **개인 기록 비서:** 개인 메모와 승인된 컨텍스트를 정리·재활용한다.
- **조사·정리 비서:** 웹 조사와 출처 기반 보고서를 만든다.
- **프로젝트 비서:** 연결 문서와 프로젝트 자료를 검토하고 계획을 만든다.
